## Design and implementation sequence

1. **Test-first result/review contract.** Add failing tests for a typed `SttResult = { text: string; detectedLanguage: 'uz-UZ' | 'fr-FR' | 'unknown'; confidence?: number; alternatives: string[]; reviewReasons: string[] }`, deterministic review-reason generation from provider/fixture metadata, and preservation of optional confidence. Do not infer a low-confidence numeric cutoff. Add at least 30 labeled fixture/metadata cases spanning Uzbek, French, and Uzbek–French code-switch, including absent/qualitatively uncertain confidence metadata, conflicting alternatives, wrong/unknown language, target-phrase-sensitive variation, and noise/empty transcript cases. Fixtures are synthetic metadata only, not recorded or uploaded audio.
2. **Test-first confirmation boundary.** Add VoiceCall regressions proving that an STT result (including one requiring review), edits, and a corrected draft do not call tutor or create a scored/user turn until explicit confirmation. Re-record clears the draft and starts listening without submission; cancel ends/dismisses the pending turn without submission. After confirmation, only the final confirmed text may reach tutor and later session feedback/memory.
3. **Minimal client implementation.** Replace the new voice-call path’s text-only callback with `SttResult`, use Cloud STT only, remove `SpeechRecognition`/`WebSpeechStt`/`HybridStt` fallback from that path, and prevent Uzbek/mixed recognition from entering Live. Preserve the separate Tutor text-dictation path unless a direct compile/API change is required.
4. **Server/provider contract.** Adapt the STT result boundary so detected language, optional confidence, alternatives and review reasons are returned/consumed consistently. Derive review reasons only from returned metadata and exercise context (expected language/target phrase/noise metadata when available); do not fabricate provider confidence or claim automatic code-switch detection is reliable. Keep existing privacy minimization, consent/quota checks, sanitization, and false readiness gates untouched.
5. **UI and integration.** Show the learner’s editable transcript and human-readable review reasons; provide explicit confirm, re-record, and cancel actions. No tutor, correction, score, feedback, or memory path may consume unconfirmed draft text.
6. **Fail-closed Live entry.** Before any token fetch, microphone access, or WebSocket creation, require a non-empty, explicitly user-confirmed `fr-FR` result whose confirmed text matches the reviewed STT text and has no review reasons. Missing, unconfirmed, empty, Uzbek, mixed/code-switch, unknown, mismatched-language, malformed, or otherwise reviewed results must stop before those operations. Do not add STT preflight or change the Live/provider route gates; keep Live hard-disabled.
7. **Verification and SDD.** Run focused STT/review and voice-call tests, `npm test`, `npm run typecheck`, `npm run build`, and `git diff --check`; inspect the diff, readiness gates, and worktree status. Update this brief, add `task-6-report.md`, and append the SDD ledger. Request independent review; do not stage or commit before the review.
